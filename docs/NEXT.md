# Next work after the source-first runtime

The root application runs six foundational Minecraft tasks. The experimental
RL-next package remains independently tested, not integrated into the live
observation/actor/learner/bridge loop. Its 18 task names are specifications only.

Prioritize complete measured vertical increments, not more unconnected libraries:
connect conditional action likelihoods and tick-aware discounting with source
and finite-difference tests; replace lossy asynchronous rollout collection with
a measured bounded on-policy protocol; integrate adaptive practice and frozen
policy-bound exams without invalidating saves silently. Add actual server-side
inventory/acquisition evidence and real fixtures before advertising crafting,
smelting, delivery or construction. Never claim all research ideas are already
in the runtime or use synthetic learning as a Minecraft skill result.

Every increment must build from a fresh clone, preserve old installations, and
repeat a live requested-population training/checkpoint/restart check. Measure
multiple learning seeds and a controlled baseline before claiming faster learning.
