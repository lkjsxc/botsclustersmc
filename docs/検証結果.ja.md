# botsclustersmc 0.3.1 修正・検証結果

2026年9月22日。添付a.zipを展開して調査し、TCP25565で32体のBotと32区画の訓練環境を起動できる修正版を作成しました。

## 原因と修正

主原因は名前変更時の設定不整合です。旧BOT_PREFIX=botsclustersmcは14文字で、13文字上限の検査に引っかかり、箱庭プラグインが起動していませんでした。Minecraft本体だけ動いていたため、見かけ上の起動成功と実際の訓練開始が食い違っていました。Bot名をbcmc00〜bcmc31に統一し、実際の待ち受け・接続先・疎通確認を25565に合わせました。

初期化エラーが通知されない問題、通常の切断・停止時にFoliaのタスク破棄を異常扱いする問題も修正しました。全区画の実ブロック読み戻し、32体全員の行動、保存と停止を確認します。失敗した場合に通常ワールドや台本操作へ切り替える処理はありません。

## 実際の検証

| 項目 | 新規起動 | 保存後の再起動 |
|---|---:|---:|
| Bot数・区画数 | 32・32 | 32・32 |
| 使用ポート | 25565 | 25565 |
| 新しいPPO更新 | 9回 | 9回 |

| 各Botの行動数の最小値 | 794 | 729 |

再起動時の重みの指紋、学習サンプル数、最適化回数は前回保存値と完全一致しました。意図的に切断したBotは20秒後に再接続し、32体での学習に戻りました。別名の見学用クライアントも接続し、スペクテイターとして保存されることを確認しました。ただし、人間のデスクトップ画面を操作するGUI試験ではありません。

破損したモデル、片方が欠けた保存ファイル、人数が不一致の進級記録は、実行バイナリがエラー終了し、残った保存データを上書きしませんでした。元の不正なBot名をJava側まで到達させる故障注入試験でも、Botを起動せずに異常を明示して停止しました。この故障注入は配布物とは別の検査専用コピーで実施しています。

19件の起動・ファイル保護テスト、24件の監視補助ツールテスト、Javaの設定・プロトコル・区画設計テスト、6件の独立した数値参照テストも通過しました。これらの単体・疑似入力検査と、実際のFoliaを動かした試験は区別しています。

## 起動と注意点

同梱バイナリはLinux x86_64・glibc2.39以上が対象です。Java21のJDK（java・javac・jar）が必要です。README.ja.mdの手順で、新しいディレクトリへ展開してください。設定はBOTS=32、SERVER_PORT=25565、BIND_ADDRESS=0.0.0.0、OFFLINE_ACCESS_ACK=trueです。既定のJavaヒープ6GiBは、想定された12GiB割り当て向けです。

元のZIPと旧ワールドは削除せず残してください。修正版には旧・検査用ワールド、学習済み重み、.env、EULA同意ファイルを入れていません。初回は新しい箱庭を生成します。提出されたZIP内には保存済みの学習stateファイルがありませんでした。

今回の検証環境は4 CPU・4GiB制限で、ヒープ2GiB・Folia2スレッドに明示設定し、Bot数は32のまま実行しました。すべての環境や長期間の安定性を保証するものではありません。外部からの接続にはルーター・ファイアウォールもTCP25565へ合わせる必要があります。それらの設定はZIPから変更されず、今回外部回線の疎通は検証していません。オフラインモードにはアカウント認証がないため、接続元を制限してください。

**学習環境の稼働と、技能の完成は別です。** 試験では実際の到達成功も記録しましたが、2回とも段階0の学習中で、固定方策による修了試験はまだ実行されていません。6課題すべての合格、人間らしい動き、自律した共同生活の完成を保証するものではありません。

RustのBot・学習器のソースと実行ファイルは、添付に含まれたものをバイト単位で維持しています。今回修正した起動処理・Javaブリッジと組み合わせ、実際に動作検証しました。Rustをこの環境で再コンパイルしたとは主張していません。詳細なログと原本の対応関係はZIP内のdocs/REPAIR-REPORT.md、evidence/repair/、bin/provenance.jsonを参照してください。

配布直前の点検では、修正前候補への端末グループSIGINT（Ctrl+C相当）が異常終了扱いになることも再現しました。最終版ではサーバー・学習器・ログ書き込みを別セッションへ分離し、中断された監視処理と保存中の繰り返し終了要求を処理します。この最後の起動管理変更を含む実際の配布ZIPの再展開・Ctrl+C・再開試験は、ZIPと並べて渡すdelivery-verificationの記録に分離しています。上の2回の計測値が、この後のシグナル変更まで検証したかのようには扱っていません。
