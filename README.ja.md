# botsclustersmc — Java製RL学習環境と推論プラグイン

[English](README.md) · [設計と制約](docs/ARCHITECTURE.md) · [学習](docs/LEARNING.md) · [検証記録](docs/VALIDATION.md)

**Minecraft内のNPCを、報酬だけで学習する共有ニューラル方策で動かす実験です。** 学習側と推論側を分離しました。学習には専用サーバーを使い、実際のワールドへの導入は `botsclustersmc.jar` と `policy.bcmc` の2ファイルです。Rust、Python、Maven、Gradle、外部の推論プロセスは通常運用に不要です。

**今回のBotは、ログインするプレイヤーではなく、村人を身体に使うサーバー内NPCです。** プレイヤーのスキン・TAB欄・認証接続・完全なバニラのサバイバル操作は再現しません。この変更でクライアントの通信・プロトコル互換・NPCごとのプロセスをなくし、Paperの公開APIだけで動く構成にしています。旧プレイヤーBotとは別の実験条件です。学習済みの万能Botは同梱しません。

## 新しいcloneから学習を始める

必要なのは **GitとJava 21のJDK**（`java` と `javac`）です。初回はインターネット接続が必要です。Linuxのほか、Windowsには同名の `.cmd` 起動スクリプトがあります。実測・対応確認の範囲は[検証記録](docs/VALIDATION.md)を参照してください。

Ubuntu 24.04の準備例:

```sh
sudo apt-get update
sudo apt-get install -y git openjdk-21-jdk

git clone https://github.com/lkjsxc/botsclustersmc.git
cd botsclustersmc
cp .env.example .env
```

[Minecraft EULA](https://aka.ms/MinecraftEULA)を読んで同意した場合だけ、`.env` の `EULA=false` を `EULA=true` に変更します。その後:

```sh
./start.sh
```

Windowsのコマンドプロンプトでは `copy .env.example .env`、編集後に `start.cmd` です。PowerShellからは `./start.cmd` とします。

初回は固定版の公式Folia 1.21.11 build14と実際のAPIライブラリを取得し、Javaソースをコンパイルして専用ワールドを生成します。番号付きの別実装や過去のZIPは不要です。初期方策はランダムです。起動はフォアグラウンドなので、端末を開いたままにしてください。

既定ポートは **25565**、バインドは `0.0.0.0` です。NPCは接続認証を必要としないため、**人間の接続はオンライン認証を有効にしたまま**です。意図的に `ONLINE_MODE=false` にする場合だけ、信頼できるLAN・VPNなどで隔離し、`OFFLINE_ACCESS_ACK=true` を明示します。ポート転送・DNS・ファイアウォールは本ソフトでは設定しません。

### 状態・観察・停止

別端末の同じフォルダーで:

```sh
./status.sh
./console.sh bots status
./stop.sh
```

`stop.sh` は停止要求です。起動端末で最終保存と終了を確認してからバックアップや再起動をします。Ctrl+Cも停止要求になります。再開は同じ `.env` で `./start.sh` です。

Minecraft Java版1.21.11で `サーバーIP:25565` に接続できます。訓練サーバーでは管理者権限なしで見学でき、入室時に上空視点へ移動します。`/bots watch` は最も進んだ個体、`/bots watch 0` は指定個体を追跡します。`/bots tour` は10秒ごとの巡回、`/bots overview` は上空の自由飛行、`/bots unwatch` は追跡解除です。目標位置の粒子とHUDで課題・試験状態を確認できます。`/bots progress` は全体の練習成績、`/bots inspect 0` は操作・速度・体力・燃焼状態などの詳細です。

`/bots pause` や `/bots resume` などの管理操作は引き続き管理者専用です。管理者権限が必要な場合は `./console.sh op 自分のユーザー名` を使います。推論プラグインでは、観察視点がゲームモードを変更するため、見学操作も既定では管理者専用です。

ブラウザーの進捗画面は、別端末で `./monitor.sh` を起動し、同じマシンの `http://127.0.0.1:8765/` を開きます。サーバーのTailscaleアドレスに公開する場合は `./monitor.sh サーバーのTailscale_IP 8765` です。Windowsは `monitor.cmd` を使います。読み取り専用で、管理コンソール・学習データ・認証情報は公開しません。ワイルドカードやパブリックIPへの直接バインドは拒否します。認証なしのリバースプロキシでインターネットへ公開しないでください。

画面は5秒ごとに更新し、学習サンプル数、実際の学習速度、練習・本番条件の試行成績、固定方策の試験、課題別人数、炎上数を表示します。15秒以上更新されなければ古い状態として警告します。**サンプル数や練習成功率が高いだけでは、技能習得・共同生活の証明にはなりません。**

```text
academy/
  server/                          専用Minecraftワールド
    plugins/BotsClustersMC/
      training.bcmc                重み・Adam・個体別カリキュラム・乱数
      status.json                  学習量・CPU・キュー・個体の状態
      history.jsonl                5秒ごとの計測履歴（上限付き）
  console.log
```

バックアップは**正常停止後の `academy/` 全体**です。チェックポイントは原子的に置き換えますが、ワールド保存と一つの原子的トランザクションではありません。破損・異なる人数・異なるモデル仕様の学習状態は拒否します。自動初期化で上書きしません。未完了エピソードや試験は再起動時に最初からやり直し、未学習の経験を学習済み扱いしません。

### 学習中の方策を独立して試験する

別端末で `./evaluate.sh` を実行すると、その時点で保存済みの学習状態から方策を固定し、専用のテストサーバーで各課題を32回ずつ試します。既定では、最も進んだ個体が現在取り組む課題までを対象にします。`./evaluate.sh --tasks 0,1,2,3,4,5,6 --cases 32` のように対象を指定することもできます。Windowsでは `evaluate.cmd` です。Pythonやnpmは不要ですが、同意済みのEULA設定と保存済みの学習状態が必要です。

`./evaluate.sh --watch --interval 600` は、試験終了から600秒後に次の方策を確認します。方策が変わっていなければ再試験しません。停止はその端末で `stop` を入力してEnter、またはCtrl+Cです。学習サーバー自体は停止しません。コード更新後は評価プロセスも起動し直してください。

評価中は、ループバックだけで待ち受ける別のMinecraftサーバーが動き、既定で最大2GiBのJavaヒープを追加使用します。通常の学習よりCPU・メモリの余裕が必要です。既定ポート25565、接続認証、実際のワールド、学習済み重み、進級記録は変更しません。

ブラウザーでは「Independent fixed-policy evaluation」に各課題の成功数／試行数と試験した方策の番号を表示します。学習中の方策の番号とは区別します。**試験の完了と、課題の成功は別です。0/32もそのまま表示し、後で更新された方策やサバイバル共同生活の保証にはしません。** 全試行の記録は `academy/server/plugins/BotsClustersMC/evaluation-details.json` に保存されます。

試験した重みと同じものを持ち出す場合は、学習を正常停止した後に評価し、再開する前に `./export.sh` を実行してください。学習を続けながら評価した過去の重みが、最新チェックポイントに残っているとは限りません。[独立評価の仕様](docs/EVALUATION.md)に停止方法・上限・結果の解釈を記載しています。

## CPUと人数

既定の `BOTS=auto` は、有効CPU数と選択したヒープから人数を決めます。現在の式は `min(2048, CPU数×64, ヒープGiB×128)` です。安全な万能最適値ではなく、明示的な設定で調整できます。

例として16論理CPU・12GiB割り当ての**新しい実験**なら、`.env` は次から始められます。

```ini
BOTS=1024
HEAP_GB=8
REGION_THREADS=auto
INFERENCE_THREADS=auto
LEARNER_THREADS=auto
```

**既に学習状態を作った後に `BOTS` だけを変更しないでください。** 人数を変える実験は、別の新しいcloneか、空の `ACADEMY=別フォルダー名` を使います。旧データの移行や人数変換は用意しません。

新版は、全員のエピソード終了を待つ方式を廃止しました。短い経験列を非同期に学習し、方策の時間差にはV-trace補正を使います。推論・勾配計算は人数に比例しない固定ワーカーで実行します。Foliaの区画群は離して配置し、近くにいる全員が一つの領域に集まる状態を避けます。スレッドを増やすだけでCPUが速くなるとは限りません。

`status.json` の重要な指標:

| 指標 | 意味 |
| --- | --- |
| `trained_samples` / `policy_updates` | 実際に学習更新へ使った経験数・更新数 |
| `learner_samples_per_second` | 直近の実学習処理量 |
| `active_agents` / `ticking_agents` | 登録個体数・直近に実際にtickした個体数 |
| `progressed_agents_since_status` | 前回表示から行動が進んだ個体数 |
| `process_cpu_cores` | JVM全体が平均何CPUコア分を使ったか |
| `process_cpu_fraction` | 利用可能CPU全体に対する使用割合（0.5なら50%） |
| `learner_queue` / `learner_stale_samples` | 学習の滞留量・古すぎて学習に使わなかった経験数 |
| `inference_queue` / `inference_rejected` | 推論待ち・キューの容量不足 |
| `course_task_population` | 各課題にいるNPCの人数 |

`process_cpu_cores` と `process_cpu_fraction` は同じ測定区間から計算します。CPU100%自体は目標ではありません。Minecraftのtick待ち、I/O、学習処理を分け、TPSや全個体の行動継続と実サンプル数を一緒に比較します。単一CPUスレッドの表示をJVM全体の負荷と混同しないでください。現在の規模試験は[検証記録](docs/VALIDATION.md)に条件付きで記載しています。数千体が一つの密集地で複雑な共同生活をする性能保証ではありません。

## JAR＋学習データを実ワールドへ持ち出す

学習側を正常停止し、起動端末で終了したことを確認してから:

```sh
./export.sh
```

実行中のAcademyからの書き出しは拒否します。`export.sh` は現行ソースをビルドし、保存済みの **`training.bcmc` から直接**推論用の方策を取り出します。別に残っている `policy.bcmc` を保存元として信用しないため、学習再開に使うモデルと書き出すモデルが食い違いません。チェックポイントが破損・欠落していれば停止し、ランダム方策や古い方策には置き換えません。

コマンドが正常終了すると、次の2ファイルが作られます。

```text
dist/deploy/plugins/botsclustersmc.jar
dist/deploy/plugins/BotsClustersMC/policy.bcmc
```

書き出しの正常終了を確認した後、対象Paper/Foliaサーバーを停止し、この配置のまま `plugins/` にコピーして通常どおり起動します。**`training.jar` はコピーしません。同じサーバーに両方のJARを入れないでください。** 外部プロセス、APIキー、Python、ネイティブライブラリは不要です。サーバーの `online-mode`・ポート・ワールド設定はプラグインから変更しません。

初回は安全のため自動生成人数が0です。管理者が立っている場所から:

```text
/bots spawn 16
/bots goal all 3 100 65 120
/bots status
```

`goal` は `対象IDまたはall`、`課題番号`、`目標x y z` の順です。上の例は課題3「移動して停止」の目標であり、学習していなければうまく到達しません。コンソールからは `bots spawn 16 world 100 65 100` のようにワールドと出現座標も指定します。

```text
/bots pause
/bots resume
/bots remove all
```

自動生成人数、ワールド、出現地点、推論スレッド等は `plugins/BotsClustersMC/config.yml` で設定します。変更はサーバーを完全停止してから行います。**`/reload` や動的プラグイン差し替えは非対応**です。

初期値の `world-edits: false` ではブロック破壊・設置・アイテム操作を禁止します。許可する場合は、**まずワールドのコピーで** `world-edits: true` にし、`edit-radius` を指定してください。学習の弱い方策は無意味な破壊・設置をする可能性があります。プレイヤー用保護プラグインがNPCの操作をすべて保護するとは限りません。

ゾンビの身体だけが日光で燃える現象は抑止します。これは学習した生存技能ではなく、NPCの身体設定です。炎・溶岩や他の個体に由来する着火まで無効にするものではありません。

**NPCの身体と持ち物は一時的で、再起動で保存・復元されません。** 実ワールドの貴重品を持たせる用途にはまだ使わないでください。方策が保存されることとNPC個体の生活が永続化されることは別です。配布モデルの書き出し成功も、技能習得の証明ではありません。

### 原木の採取を見学する

`/bots inspect ID` では、選択した移動・視線・掘る操作を名前で表示し、持ち物、掘っているブロック、継続中の採掘tick、そのエピソードで実際に壊した個数・回収した個数を確認できます。掘るボタンを押しただけでは成功扱いしません。進捗画面も、課題ごとの現在の受講者の成績と、過去に試験へ合格した人数を分けて表示します。受講者の入れ替わりで成績の平均が変わることがあります。

現在保存されている方策を学習から切り離して実地試験する開発者向けコマンドは、`tests/holdout.py --checkpoint academy/server/plugins/BotsClustersMC/training.bcmc --output .build/my-holdout --tasks 0 1 2 3 4 5 6 --cases 32` です。実行には、EULAへ同意したうえで `EULA=true` とPythonを指定してください。通常の起動・見学にはPythonは不要です。この試験は別のローカルサーバーを使い、本番の学習を停止したり、試験結果を学習へ混ぜたりしません。失敗した試行もそのまま記録します。

## 何を学ぶのか

18課題は、移動・停止・旋回・視線・段差、原木破壊と回収、設置、板・棒・作業台・木／石のツルハシのクラフト、丸石採掘、鉄精錬、チェスト搬入、足場、原木から作業台までの連鎖です。ニューラル方策が移動・視線・ジャンプ・掘る／使う・持ち替え・個々のスロットクリックを選びます。経路探索・自動照準・クラフトマクロ・模倣学習・LLMは使いません。

観測は512個の数値に固定しています。周囲のブロック・在庫・課題ID・目標位置・残り時間に加え、自分基準の方向と速度、停止時間、水・溶岩、最大8体の近傍対象、最大12ブロック先までの8方向の粗い探査を与えます。チャンク全体をBotごとに送る方式ではありません。未読み込み・別スレッド管理の領域は未知として扱い、見学者のスペクテイターは入力から除外します。映像だけを見て学ぶ方式ではありません。易しい練習にはリセット時の材料配置補助がありますが、全難度の確認と凍結試験には使いません。個体ごとに段階と復習を管理し、一個体の試験や失敗で全員を停止させません。[学習仕様](docs/LEARNING.md)に評価条件と補助を記載しています。

クラフト・採掘は公開APIで作った限定されたNPC用操作系です。全バニラレシピ、空腹、耐久度、戦闘、ネザー攻略、永続的な共同生活などは実装していません。**18課題の実行可能性テストと、ニューラル方策が18課題を習得したことは別です。**

## 互換性と更新方針

旧実装・旧重み・旧 `.env` の互換性は維持しません。現在のコード・ファイル名・保存先は一組だけです。旧サーバーを旧版の停止方法で止めて保管し、**新しいcloneから始めてください**。過去のワールドや学習データは自動削除しません。

プラグインはPaperの公開APIを使い、Minecraft内部クラス名・通信プロトコルに依存しません。ただし「全バージョン対応」とはしていません。Paper派生版、ARM64、macOS、他プラグインとの併用は、個別の実サーバー検証が必要です。Paper 26.1以降はサーバー側にJava25が必要です。対応を確認した版・OS・試験条件は[検証記録](docs/VALIDATION.md)を確認してください。

### 作業台での操作を確認する

`/bots inspect 0` は、NPCが開いているメニュー、カーソルに持った素材、完成品の
プレビュー、各スロットの内容も表示します。見学中のHUDでもメニューとカーソルを
確認できます。自分のインベントリを開いているだけなのか、実際の作業台を使って
いるのかを区別できます。表示からNPCの持ち物を操作することはできません。

クラフトの進捗判定は、2×2と3×3の格子を区別し、完成品プレビューを素材として
数えないよう修正しました。練習用の補助と厳密な試験条件の違いは
[作業台学習の仕様](docs/STATIONS.md)に記録しています。

作業台を開く練習はHUDに `practice: open target station` と表示します。この短い
練習の成功はツルハシ完成を意味しません。本番条件の試行と固定方策の試験では、
従来どおり実際の完成品を要求します。
