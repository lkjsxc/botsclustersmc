# botsclustersmc 0.5.0 — 64体のRL Academy

Minecraft実行本体に、経験収集の同期、適応型カリキュラム、条件付きGUI方策、経過tick対応のPPO、18段階の環境と成功判定を接続しています。研究部品を別に移植する必要はありません。`git clone`して起動すると、64体が個別の訓練区画で、ランダム初期化した共有ニューラル方策から学習します。

**実装された課題、通常操作で到達できる課題、学習して習得した課題は別です。** 学習済みモデルは同梱しません。検証したソース・実行条件・結果・限界は[検証記録](docs/VALIDATION.md)を参照してください。

## Linuxサーバーでの初回起動

対象割り当ては16論理CPU・12GiB RAM・120GBです。これは性能保証ではありません。検証対象はLinux x86_64、Java 21 JDK、Minecraft Java Edition 1.21.11です。GPU・LLM API・Pythonは通常の起動・学習に不要です。macOSやWindowsから使う場合はLinuxサーバーにSSH接続して、そこで以下を実行してください。初回ビルド前に20GiB以上、運用中は既定で10GiB以上の空きを確保します。

Ubuntu 24.04系での準備例です。

```bash
sudo apt-get update
sudo apt-get install -y git curl ca-certificates build-essential pkg-config cmake unzip util-linux openjdk-21-jdk

git clone https://github.com/lkjsxc/botsclustersmc.git
cd botsclustersmc
cp .env.example .env
```

Minecraft EULA（https://aka.ms/MinecraftEULA）を読み、自分で同意した場合だけ起動してください。

```bash
EULA=true ./start.sh
```

初回は固定版のRust、Azalea、Gson、Foliaと必要な依存物を取得し、テスト・ビルド・実際のFolia APIに対するプラグインのコンパイルを行います。続いて、新しい専用ワールドに8列×8行の64区画を作り、`bcmc00`〜`bcmc63`を接続します。旧ZIPやGitHub Actionsの成果物は不要です。

既定の設定は次のとおりです。変更はルートの`.env`で行います。

```bash
BOTS=64
SERVER_PORT=25565
BIND_ADDRESS=0.0.0.0
OFFLINE_ACCESS_ACK=true
JAVA_HEAP_GB=6
FOLIA_THREADS=6
VIEW_DISTANCE=3
SIMULATION_DISTANCE=3
BOT_VIEW_DISTANCE=3
SPECTATOR_VIEW_DISTANCE=12
```

**オフラインモードにはアカウントの本人確認がありません。** TCP 25565への接続を信頼できるLAN・VPN・ファイアウォールで制限してください。`OFFLINE_ACCESS_ACK=true`は認証やファイアウォールを設定しません。別のMinecraftサーバーが25565を使用中の場合は、そちらを先に正常停止してください。

全員の接続と行動を確認した後は、別端末の同じフォルダーから状況を確認できます。

```bash
./status.sh
cat academy-v2/state/academy-status.json
```

`policy_version`・`trained_samples`が増えると実際の学習更新が進んでいます。各Botは同じ方策のまま経験を集め、必要量を集めてエピソードを終えたBotから更新待ちになります。全64体が揃うまでの待機は正常な同期動作です。全体の平均成績だけで進級させたり、遅いBotを勝手に除外したりはしません。

## Minecraftから観察する

**Java版Minecraft 1.21.11**で`サーバーIP:25565`に接続します。このソフトはDNSやルーターのポート転送を変更しません。人間はスペクテイターとして参加し、学習に介入せず観察します。

| 操作 | 内容 |
| --- | --- |
| `/academy` | 64体を2ページに分けた一覧。クリックでその区画へ移動 |
| `/academy watch 63` | 番号0〜63のBotを指定して観察 |
| `/academy next`、`/academy prev` | 次・前の区画へ。端では折り返し |
| `/academy overview` | 全体を上から見渡す |
| `/academy tour` | 12秒ごとの自動巡回を切り替え |
| `/academy view 16` | 自分の描画距離を変更（3〜16チャンク） |

観察者の既定描画距離は12チャンク、Botは3チャンクです。観察のために64体すべてのチャンク通信やシミュレーション距離を増やさない構成です。**Minecraftクライアント側の描画距離も12以上にしてください。** 16に変更した場合はクライアントも16以上にします。エンティティ描画距離を極端に低く設定していると、地形が見えても遠くのBotは見えない場合があります。

画面下部に選択中Botの課題、練習・復習・全難度確認・試験・待機の状態、成功率の移動平均、難度、方策バージョンを表示します。TAB欄では全体の段階・学習サンプル数・更新待ち人数を確認できます。成功率の移動平均は参考値で、進級試験の合格率とは異なります。観察UIは英語です。

## 停止、再開、バックアップ

`start.sh`はフォアグラウンドで動きます。起動した端末を閉じず、別端末から次を実行してください。

```bash
./console.sh "list"
./stop.sh
```

`stop.sh`は停止要求です。起動端末に`Clean shutdown: model, curriculum and world saved.`が表示され、終了するまでバックアップや再起動を始めないでください。Ctrl+Cでも保存後に停止します。再開は同じフォルダーで`./start.sh`です。初回のEULA同意は専用サーバーに記録されます。

```text
academy-v2/
  server/                 ワールド
  state/training.bcmc      方策・Adam・乱数・カリキュラムをまとめた学習状態
  state/status.json        全体の学習状況
  state/academy-status.json 個別課題と同期状態
  logs/                   学習・エピソード・サーバーログ
```

バックアップは正常停止後の`academy-v2/`全体を保存します。単一の学習状態ファイルは原子的に置き換えますが、Minecraftワールドまで含めた一つの原子的トランザクションではありません。破損時に別々の時点のファイルを混ぜたり、自動初期化で上書きしたりしないでください。

停止時にまだ更新されていない経験と未完了の操作は、`academy-status.json`の`cohort_samples`、`local_untrained_samples`、`unfinished_actions`に残します。再起動でエピソードは新しい識別子と環境リセットから始まります。未完了操作を成功扱いしたり、後の方策に混ぜて学習したりはしません。

## 0.4.0・旧32体版から更新する

まず**更新前の版の`./stop.sh`で旧サーバーを停止**し、正常終了を確認してください。その後、リポジトリを更新します。

```bash
git pull --ff-only
```

既存の`.env`は上書きされません。そこに`BOTS=32`が残っていれば、**`BOTS=64`へ変更**してください。`BOT_VIEW_DISTANCE=3`と`SPECTATOR_VIEW_DISTANCE=12`は未設定なら既定値が使われます。新しいAcademyの初回起動では、EULAに同意した場合に`EULA=true ./start.sh`を実行します。

旧`academy/`は削除も移植もせず、新版は独立した`academy-v2/`を作ります。観測形式、条件付き方策、課題、保存形式が変わるため、**旧32体版の重みを引き継がず、新しく学習します**。旧学習データを`academy-v2/state/`へコピーしないでください。既に作ったv2の人数も勝手に変更できません。別人数の実験は別のcloneで行います。

## 18段階と学習の意味

1〜5は移動・停止・旋回・視線・段差の基礎、6〜8は原木の破壊・回収・ブロック設置です。9〜14では板材、棒、作業台、木のツルハシ、丸石、石のツルハシへ進みます。15〜18は鉄精錬、チェストへの搬入、3ブロックの足場、原木の採掘から作業台のクラフトまでをつなぐ課題です。

材料・道具・作業台・かまどを初期状態として用意する課題があります。易しい練習では、クラフト枠への一部材料配置やコンテナーを開いた状態から開始する補助もあります。これは**リセット時の初期条件**であり、Botに代わって操作する補助ではありません。全難度の確認課題と進級試験には、このメニュー・レシピ補助を使いません。

報酬だけで学習し、経路探索・自動照準・模倣学習・LLMによる操作は通常のBotにありません。ただし、目標座標、アイテム状態、設計済み報酬を使う状態ベースのRLであり、映像だけを見て学ぶ方式ではありません。成功はサーバーが確認した結果で採点します。

各Botの失敗・上達・忘却傾向から難度と復習配分を調整します。全員が現在段階を40回以上練習し、8回以上の全難度確認とその成績条件を満たすと方策を凍結して試験します。各Botが現段階16回中14回以上、過去の各段階4回中3回以上成功して初めて進級します。**起動し続けるだけで時間順に解放されるわけではありません。** 18段階の実装は、全技能の習得・人間らしさ・自由なサバイバル・64体の共同生活の達成を意味しません。

## 診断と検証

```bash
./scripts/doctor.sh
./scripts/diagnostics.sh
```

診断アーカイブは`.env`、重み、ワールドを含めませんが、ログ中の名前・IP・パスは共有前に確認してください。詳しくは[トラブルシューティング](docs/TROUBLESHOOTING.md)と[検証範囲](docs/VALIDATION.md)を参照してください。

開発者用の`smoke.sh`は隔離した実サーバーで学習・保存・再開を検証します。`scripts/test-live-fixtures.sh`は別の隔離環境と別のRust実行ファイルで、台本による通常入力から各課題と観察操作を検証します。後者は学習済みBotではなく、通常学習に混入しません。どちらも明示的なEULA同意が必要です。開発用検証ではPython 3も使用します。
